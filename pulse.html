01 / Formats

Three formats,
one model.

Pulse ships in three complementary formats. Each serves a different runtime. The source-of-truth BF16 weights, a portable GGUF for any CPU/GPU stack, and a native Core ML package for Apple Silicon — the final destination.

Full precision · Source
BF16
Safetensors
final/model.safetensors
Full-precision weights. The authoritative checkpoint for further fine-tuning, distillation, or conversion to other formats. Loads directly with transformers.
Size 5.7 GB
4-bit quantized · CPU / GPU
Q4_K_M
GGUF
gguf/pulse-q4_k_m.gguf
K-quant 4-bit via llama.cpp. Runs on any laptop CPU, Ollama, or LM Studio. Quality loss vs BF16 is minimal for coaching tasks. Powers the public demo Space.
Size 1.8 GB
INT4 · Apple Neural Engine
Core ML
INT4
coreml/pulse.mlpackage
Apple's native format. Runs on ANE, Metal, or CPU. No Python runtime, no bridging hacks. The whole point of the project — this is the iOS app engine.
Size 1.6 GB

2 commands. Runs locally on any Mac or Linux machine.

transformers

Core ML
.mlpackage for iOS / macOS. Native ANE inference.
# Download the GGUF
huggingface-cli download Abiral129/Pulse3b \
  gguf/pulse-q4_k_m.gguf --local-dir .

# Create Modelfile
cat > Modelfile <<'EOF'
FROM ./gguf/pulse-q4_k_m.gguf
TEMPLATE """<|im_start|>system
{{ .System }}<|im_end|>
<|im_start|>user
{{ .Prompt }}<|im_end|>
<|im_start|>assistant
"""
SYSTEM """You are Pulse, a personal wellness coach."""
PARAMETER temperature 0.7
PARAMETER top_p 0.9
PARAMETER repeat_penalty 1.1
PARAMETER num_ctx 2048
EOF

ollama create pulse -f Modelfile
ollama run pulse "I've been sleeping 5 hours. Help."
./llama-cli \
  -m gguf/pulse-q4_k_m.gguf \
  -p "You are Pulse, a wellness coach." \
  -cnv \
  --temp 0.7 \
  --top-p 0.9 \
  --repeat-penalty 1.1 \
  -c 2048
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

tok = AutoTokenizer.from_pretrained(
    "Abiral129/Pulse3b", subfolder="final"
)
model = AutoModelForCausalLM.from_pretrained(
    "Abiral129/Pulse3b", subfolder="final",
    torch_dtype=torch.bfloat16, device_map="auto",
)

messages = [
    {"role": "system", "content": "You are Pulse, a wellness coach."},
    {"role": "user",   "content": "My resting HR jumped to 88. Help."},
]
ids = tok.apply_chat_template(
    messages, add_generation_prompt=True, return_tensors="pt"
).to(model.device)
out = model.generate(ids, max_new_tokens=300, temperature=0.7, top_p=0.9)
print(tok.decode(out[0][ids.shape[1]:], skip_special_tokens=True))
import coremltools as ct
from transformers import AutoTokenizer
import numpy as np

tok = AutoTokenizer.from_pretrained(
    "Abiral129/Pulse3b", subfolder="final"
)
mlmodel = ct.models.MLModel("coreml/pulse.mlpackage")

ids = tok(
    "Hello Pulse, I need help with sleep.",
    return_tensors="np"
).input_ids.astype(np.int32)

result = mlmodel.predict({"input_ids": ids})

07 / Limitations

Read this
before shipping.

  • ⚠
    Not a medical device Pulse is a wellness coach. It will refuse to diagnose, but it can still confidently make wrong claims. Do not let it gate medication decisions, mental health crises, or any clinical pathway.
  • ⚠
    3B reasoning ceiling It is not GPT-4. Multi-step reasoning, math, and tasks requiring tool use will underperform a frontier model. For "give me a 4-step sleep plan" it holds up; for complex clinical analysis it doesn't.
  • ⚠
    English-first Training data leans heavily English with some Spanish. Other languages will produce weaker, less reliable responses.
  • ⚠
    Quantization drift Q4_K_M is great; INT4 Core ML is more aggressive. Expect occasional phrasing weirdness in the Core ML build relative to BF16.
  • ⚠
    No session memory The model doesn't learn from your conversations between sessions. That's a feature for privacy and a bug for personalization — solved at the app layer, not the model layer.
08 / Roadmap

What comes
next.

1

iOS app on Core ML

Native generation loop in Swift, on-device chat, daily check-ins, basic wellness tracking. No server, no account required for inference.

In progress
2

Distillation to 1B–2B

Push to smaller sizes with less quality loss for older iPhones and lower-RAM devices. A14 Bionic can host a well-distilled 1.5B model comfortably.

3

DPO / Preference tuning

Target the main failure modes — "stop apologising" and "give me numbers, not vibes" — using direct preference optimisation on collected coach-specific feedback.

4

Multilingual expansion

Spanish first, then Portuguese and French. Native speakers as evaluators, not just automated metrics.

5

Optional tool use (on-device)

Sleep tracker, HR data, calendar — all opt-in and processed locally. The model gets structured context; user data never leaves the device.
